# 二游游玩清单实施方案

状态：原始设计提案；本地首版已实现。实际采用同一页面的 `?mode=anime` / `?mode=games` 切换，共用 `app.js`、`poster.js`，通过 `modes.js` 提供模式配置；没有新增独立 games.html。目录从已核对的 Bangumi ID 白名单同步，首版 24 款。以下保留原始方案作为设计参考，实际维护步骤见 README。

## 产品定位

在番迹现有界面增加「动画 / 二游」入口。二游页的主要流程是：搜索游戏 → 点击封面标记玩过 → 编辑清单 → 生成 PNG。首版「玩过」由用户自行判断，不要求通关，也不等同于当前仍在游玩。

建议使用 `games.html` 作为独立入口，动画页仍为 `index.html`，两页共享样式和通用组件。相对链接兼容当前 GitHub Pages 子路径部署；开发服务器也可以直接访问 `/games.html`。

## 延续现有风格

- 保留浅灰背景 `#f8f9fc`、白色面板、蓝色强调 `#425ce8`、圆角、轻阴影和中文字体。
- 保留顶部固定筛选栏、中间封面网格、底部固定清单操作栏，以及选中后的蓝框和勾选标记。
- 顶部加入动画与二游导航，二游页标题使用「二游游玩清单」，引导语使用「勾选玩过的二游，生成你的游戏清单」。
- 底部改为「我的游玩清单」「已玩过 N 款」「生成我的二游清单」。编辑、清空与撤销保持原有行为。
- 游戏卡片建议使用独立的方形封面样式，优先整理可辨认的游戏图标。动画仍保留竖版封面；不要把横版游戏宣传图直接裁成动画比例。
- 手机沿用三列网格，筛选控件控制数量；继续通过 ResizeObserver 计算固定栏占位，避免导航增加后遮挡内容。

## 首版交互

| 区域 | 建议行为 |
| --- | --- |
| 搜索 | 中文名、外文名、简称和别名；沿用 NFKC 规范化 |
| 类型筛选 | 使用目录约定的玩法标签，例如动作、回合制、塔防、射击、其他；允许游戏有多个标签 |
| 排序 | 默认目录顺序、名称顺序；目录顺序是人工维护顺序，不标称人气榜 |
| 只看已选 | 仅显示本页勾选的游戏 |
| 卡片 | 点击切换玩过/未选，支持键盘与 aria-pressed |
| 海报 | 昵称 +「玩过的二游」+ 总款数 + 游戏封面与名称；首版不插入年份卡片 |

首版不沿用季度、近三年范围、动画类型、Bangumi 评分或首播时间排序。游戏上线时间与用户入坑时间不同，不能借上线年份暗示游玩年份。

「在玩 / 退坑 / 回坑」、个人评分、入坑日期、账号信息及云同步可以后续扩展，不作为生成清单的前提。

## 目录与收录口径

建议先维护一份几十款规模的静态目录，人工确认收录范围和封面。这里的「二游」采用项目编辑口径，而非声称存在统一客观分类：首版面向二次元角色导向的持续运营游戏，边界条目经维护者确认后添加。该口径是产品建议，尚未验证具体数据源的覆盖能力。

- 原则上一款游戏一个稳定 ID；不同区服与平台合并，续作独立。用户勾选任一区服都计入同一作品。
- 已停服作品仍可记录为玩过，不因为无法继续游玩而删除。
- 未正式上线的作品首版不收录；若以后记录测试体验，应单独标明。
- 不套用动画目录近三年的自动淘汰规则。名称变化只修改展示字段，稳定 ID 不变。
- 每项保存资料和图片出处，以官方页面核实名称；上线日期、运营状态等易变化字段在需要展示时再核实并引入。
- 封面整理为同源静态文件，避免浏览器 Canvas 导出依赖第三方图片跨域配置；本地缓存不代表获得图片使用授权。

建议数据文件为 `dist/data/games.json`，示意结构如下。这里没有真实游戏资料，也不应把示例作为上线目录。

```json
{
  "schemaVersion": 1,
  "updatedAt": "YYYY-MM-DD",
  "sourceLabel": "人工整理，资料出处见目录",
  "items": [
    {
      "id": "game-example",
      "title": "示例游戏",
      "original": "Example Game",
      "aliases": ["示例简称"],
      "genres": ["动作"],
      "cover": "covers/games/game-example.webp",
      "sources": [],
      "coverSource": ""
    }
  ]
}
```

游戏记录使用独立键 `anime-review:games:selected:v1`，值为稳定 ID 字符串数组。动画继续使用现有 `anime-review:selected:v1` 数字数组；昵称可继续共用。游戏记录恢复应去重并校验类型，目录暂缺的 ID 保留在存储中但不计入可导出数量，避免目录回滚或短暂缺项导致历史选择消失。主动清空则清除全部游戏选择，包括暂缺条目，且可撤销。

| --- | --- |
| `dist/index.html` | 增加到二游页的导航，保留动画筛选与原有入口 |
| `dist/games.html`（新增） | 游戏页结构和文案，不显示年份、季度、动画类型或评分 |
| `dist/style.css` | 复用颜色、固定栏、网格和弹窗；增加导航与游戏卡片方形比例，以页面类名限定作用范围 |
| `dist/app.js` | 动画入口保持原行为；抽取确实重复的存储安全读写、图片回退及弹窗辅助函数，不立即将整页改写为通用框架 |
| `dist/games.js`（新增） | 加载游戏目录，负责选择、清单编辑、游戏筛选、本地保存、PNG 预览和下载 |
| `dist/game-catalog.js`（新增） | 游戏筛选、稳定顺序和字符串 ID 恢复；不能直接套用只接受整数 ID 的 restoreSelection，或以数字相减作兜底的 sortItems |
| `dist/poster.js` | 抽取 Canvas 的文字换行、图片加载、封面裁切与单图尺寸限制；动画默认行为保持不变 |
| `dist/game-poster.js`（新增） | 使用通用绘图辅助函数，输出方形封面网格和「款」单位；不用动画 posterCells 的年份分组，也不标注 Bangumi 来源 |
| `dist/data/games.json`、`dist/covers/games/`（新增） | 游戏独立目录和同源图片，不受动画同步覆盖 |
| `scripts/serve.mjs` | 如使用 WebP，补充 `.webp: image/webp` 响应类型 |
| `package.json`、`test/` | 将新入口纳入语法检查，增加游戏数据和选择恢复测试 |
| `README.md` | 增加二游入口、收录口径、存储边界和目录维护说明 |

现有 `scripts/sync-catalog.mjs` 专为动画编写，不应用于抓取二游。首版人工维护 JSON；后续确认可靠数据源后，再新增独立同步脚本。当前 `dist/**` 已纳入 GitHub Pages 部署触发路径，正常新增静态文件无需新增服务端。

## 海报与验收

海报保留现有蓝色顶线、浅底色、昵称和手机长图形式。建议仍按 1080px 宽、每行四格输出，使用方形游戏封面；按目录顺序排列，不受页面临时筛选和排序影响。导出应包含所有已选且目录可用的游戏，缺图显示名称；保留大图按比例降低分辨率的策略。

实施后重点验证：

1. 动画原有选择与昵称可恢复，两个页面的选择和清空操作互不影响。
2. 游戏别名、全角字符、组合筛选与只看已选正确；编辑清单始终覆盖全部选择，不受当前搜索影响。
3. 损坏的存储、字符串 ID、重复 ID、暂缺目录条目、目录重新出现及无法写入存储的场景有明确行为。
4. 海报包含完整选择、无重复遗漏，不出现动画单位、首播年份卡片或错误资料来源；缺图和长昵称仍能导出。
5. 手机与桌面上固定栏不遮挡卡片和操作，键盘能完成选择、编辑、关闭弹窗与下载。
6. 运行既有 `npm run check` 和新增检查，并在浏览器实际导出 PNG；语法和纯逻辑测试不能代替视觉验证。

建议落地顺序：先确认目录口径并整理真实游戏与图片，再实现独立入口和记录，最后复用海报绘图并做回归。首版继续采用无登录、无数据库的静态站架构。
